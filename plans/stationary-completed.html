Implementation plan · Dots / Herdr

Stationary: declarative Herdr layouts

Brief

Turn the local plugin into Stationary, with Herdr workspace layouts defined in a compact named TOML recipe. Layout keys contain tab keys; each tab declares an inline root pane and ordered split records. The plugin manifest selects the recipe by name.

Scope and outcome

Current design

local-plugins/default-layout/apply-layout.sh contains every tab label, pane label, split direction, ratio, command, and focus decision as shell statements.

POSIX shelljqhardcoded topology

Proposed design

local-plugins/stationary/layouts.toml owns the topology. The renamed Stationary hook validates the selected layout, interprets ordered split records, and preserves the fresh-workspace and failure guards.

TOML recipeyq → JSONgeneric executor

Explicit non-goals

  • No project-specific auto-selection, per-workspace overrides, or interactive picker.
  • No recursive geometry language, arbitrary pane moves, agent startup, or new Go/Rust binary.
  • No change to the Servers tab, Nvim startup, final focus, or fresh-workspace guard. Work gains one idle shell below Nvim.

03

Recipe contract

common/.config/herdr/local-plugins/stationary/layouts.toml 
[layouts.default]
focus = "Work"

[layouts.default.tabs.Work]
order = 1
root = { pane = "Agent" }
splits = [
  { source = "Agent", direction = "right", ratio = 0.25, pane = "Nvim", run = "nvim", focus = true },
  { source = "Agent", direction = "down", ratio = 0.65, pane = "Shell I" },
  { source = "Nvim", direction = "down", ratio = 0.80, pane = "Shell II" },
]

[layouts.default.tabs.Servers]
order = 2
root = { pane = "Server I" }
splits = [
  { source = "Server I", direction = "right", ratio = 0.50, pane = "Server II" },
  { source = "Server I", direction = "down", ratio = 0.50, pane = "Server III" },
  { source = "Server II", direction = "down", ratio = 0.50, pane = "Server IV" },
]

Keys carry names

default is the layout key. Work and Servers are tab keys. Each tab needs one header; roots and splits stay compact inside it.

Order is explicit

Tab records use unique contiguous order values. Split array order is TOML document order. The first tab reuses the event tab and root pane.

Commands are optional

run is an optional non-empty, single-line shell command string on a root or split pane. Commands run after all topology mutations.

Focus follows creation

A tab may mark at most one root or split pane with focus = true. Split focus maps directly to Herdr’s pane split --focus; no marker leaves the root focused. The layout names the final tab.

04

Runtime flow

The complete document and every named layout are parsed and validated before any tab or pane mutation.

Execution contract

The hook keeps logical pane names mapped to opaque Herdr pane IDs. For each ordered tab it renames or creates the root, applies splits in recipe order, records returned IDs, and passes --focus only while creating the pane marked by the recipe. After all topology mutations it runs optional commands and focuses the layout’s named tab. A root focus marker requires no pane command.

05

Validation and failure behavior

Closed v1 schema

  • The document is a table with exactly one key, layouts. layouts is a non-empty table keyed by unique, non-empty, single-line layout names. Every layout is validated, including layouts not selected for this event.
  • The hook accepts exactly one non-empty layout-name argument. The selected layout must exist. Each layout is a table with exactly focus and tabs; focus is a string naming one of its tabs and tabs is a non-empty table.
  • Each tab value is a table with exactly order, root, and splits. Tab keys are non-empty, single-line labels without control characters. Orders are unique contiguous integers from 1.
  • root is a table with allowed keys pane,run,focus; pane is required. splits is an array of tables with exactly the required source,direction,ratio,pane keys and optional run,focus keys. Unknown keys fail preflight.
  • Ratios are JSON numbers strictly between 0 and 1. Directions are right or down. Every present focus is a boolean.
  • Pane labels are unique within a tab, non-empty, single-line strings without control characters. Every split source names the root or an earlier split pane.
  • run, when present, is a non-empty single-line string without control characters. Each tab has zero or one focus = true; zero means its root pane.
  • Empty split arrays are valid for one-pane tabs. TOML numeric spelling is not preserved: yq/jq emits canonical CLI values such as 0.25, 0.5, 0.65, and 0.8.

Implementation slices

Slice 1

Compile one named recipe into the target layout

Start red by requiring exactly one layout argument; the current static hook wrongly succeeds without it. Add layouts.toml, pass default from the manifest, then prove recipe control with a temporary copied plugin fixture whose Work ratio is 0.20. The path is TOML → yq → validated JSON → shell interpreter → recorded Herdr calls. The copied recipe and fake CLI are the temporary seams; sh test.sh is the proof.

Acceptance criteria

  • Changing a ratio in TOML changes the live split without shell edits.
  • Tab keys become Herdr tab labels; pane names resolve split sources.
  • A focused split is created with --focus; an unmarked tab keeps its root focused.
  • The manifest-selected layout is the only recipe applied.
  • herdr plugin list reports dots.stationary and no dots.default-layout.
  • Invalid recipes never mutate a fresh workspace.
  • Work matches the four-pane reference; Servers remains the existing 2×2 grid.
