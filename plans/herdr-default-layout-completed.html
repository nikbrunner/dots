Implementation plan · dots / Herdr

Apply one default layout to every new Herdr workspace

Brief

Every new workspace and worktree gets the same static two-tab layout. Neovim starts in the Nvim pane; every other pane stays at its idle login shell. The setup lives in dots and does not depend on a third-party layout plugin.

01

Scope

A small local plugin subscribes to Herdr’s workspace.created event. Herdr 0.8 emits that event for ordinary workspaces and worktree workspaces, so one path covers both cases.

Included

  • Create the Work and Servers tabs in fresh workspaces.
  • Name all seven panes and start Neovim only in the Nvim pane.
  • Track and link the local plugin through dots.
  • Make the install script the source of truth instead of a tracked runtime registry.
  • Remove herdr-plus and its worktree layout.
  • Unlink the stale, untracked herdr-navigator plugin.

Not included

  • Per-repository or per-branch layouts.
  • Automatic server, shell-command, or agent startup.
  • A layout picker or editable layout schema.
  • Changes to existing or restored workspaces.
  • Installation of 3mmdrew/herdr-layout.
02

Current state and target

Current

cloudmanic.herdr-plus applies a tracked TOML layout only to worktrees. Ordinary workspaces keep Herdr’s single pane. Its project picker is bound to alt+p.

worktree onlythird-party config

Target

dots.default-layout owns one static layout and applies it to every new workspace, including workspaces created for new or opened worktrees. Herdr’s event context supplies the workspace, tab, and root-pane IDs.

all new workspacesowned in dots

Plugin audit

The live registry contains herdr-navigator, but install-plugins.sh does not track it. Its local manifest is unavailable and its job overlaps with the tracked helm-herdr plugin. The implementation unlinks it instead of adding it to the installer. The generated plugins.json registry also stops being tracked and symlinked, so install-plugins.sh becomes the portable source of truth.

04

Event and command flow

Only a fresh workspace is mutated. Existing and restored workspaces never enter this flow.
common/.config/herdr/local-plugins/default-layout/herdr-plugin.toml 
id = "dots.default-layout"
name = "Dots Default Layout"
version = "0.1.0"
min_herdr_version = "0.8.0"
platforms = ["linux", "macos"]

[[events]]
on = "workspace.created"
command = ["sh", "apply-layout.sh"]
05

Vertical slices

Slice 1

Turn one fresh workspace into the final layout

Create the manifest, POSIX shell hook, and a fake-Herdr test. The test supplies event IDs, records CLI calls, and returns deterministic JSON IDs. It proves tab names, pane names, split directions, ratios, command order, and the no-command rule.

temporary seam: fake herdr CLIproof: sh test.sh
Slice 2

Register through dots and prove both creation paths

Link the local source through symlinks.yml and install-plugins.sh. Before installation, the script removes ~/.config/herdr/plugins.json only when it is a symlink; Herdr then recreates a regular machine-local registry. The tracked smoke-test.sh installs cleanup traps before creating anything, records each resource ID immediately, creates a disposable ordinary workspace and a worktree workspace, waits for two tabs and seven named panes, checks process state and geometry, then removes workspace resources before branches and temporary directories.

boundary: dots → plugin registry → live Herdrproof: sh smoke-test.sh
Slice 3

Remove overlapping plugin state

Uninstall herdr-plus, remove its installer entry, layout file, and alt+p keybinding. Unlink the untracked herdr-navigator entry. A final registry check must contain only tracked plugins plus dots.default-layout.

proof: herdr plugin list --json

apply-layout.sh command contract 
# Inputs injected by Herdr
HERDR_BIN_PATH, HERDR_WORKSPACE_ID, HERDR_TAB_ID, HERDR_PANE_ID

# Existing root becomes Work / Nvim
tab rename → pane rename → split right 0.70 → split Agent down 0.65

# New tab becomes a 2 × 2 Servers grid
tab create --no-focus → split right 0.50
→ split Server I down 0.50 → split Server II down 0.50

# Start the only automatic command, then focus Work
pane run Nvim nvim → tab focus Work

# Every CLI response is parsed with jq; any mutation failure stops the script.

Verification and acceptance

Automated checks

  • sh -n apply-layout.sh test.sh smoke-test.sh
  • shellcheck apply-layout.sh test.sh smoke-test.sh
  • sh test.sh
  • dots link without missing-source errors
  • ~/.config/herdr/install-plugins.sh after linking
  • test -f ~/.config/herdr/plugins.json && test ! -L ~/.config/herdr/plugins.json
  • sh smoke-test.sh against the running Herdr session
  • herdr plugin list --plugin dots.default-layout --json

Live checks

  • Create and inspect one disposable workspace.
  • Create and inspect one worktree from a temporary Git repository.
  • Confirm Work stays focused, Nvim runs nvim, and every other pane stays at its login shell.
  • Assert split directions and ratios through .result.layout.splits with numeric tolerance.
  • Remove all disposable workspaces, worktrees, branches, and temporary directories through traps.
  • Confirm cloudmanic.herdr-plus and herdr-navigator are absent.

Acceptance

A newly created ordinary workspace and a newly created worktree both show the two planned tabs, seven names, planned ratios, and Neovim running only in Nvim. Existing workspaces remain unchanged. The live plugin list matches the tracked installer, and plugins.json is a regular machine-local file.
